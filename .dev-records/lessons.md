# 经验总结

## 2026-08-01 - 版权内容与源码使用文件系统边界隔离

### 场景
兼容引擎需要读取本地版权内容，但开源仓库不得包含这些文件。

### 经验
应先把正式 Git 根限制在源码工程，再使用忽略规则和版权扫描作为第二、第三层防护。

### 下次建议
任何暂存或提交前先验证 Git 顶级目录、候选文件和忽略结果。

## 2026-08-01 - 进程退出码不能代替测试证据

### 场景
Unity 带 `-quit` 返回 0，但没有执行测试或生成 XML。

### 经验
测试入口必须验证本次运行生成的隔离结果文件、实际执行数量和失败数；进程退出 0 只是附加信号。

### 下次建议
所有命令行测试器都应拒绝陈旧、缺失、空白和零测试结果，并为超时或强制收尾保留明确诊断。

## 2026-08-02 - 黑盒工具兼容必须拆分四种结论

### 场景
旧 GUI 工具可以打开、生成和提取 MIX，但不同 writer 会产生不同布局字节，工具还会隐式加入名称数据库或忽略零字节输入。

### 经验
应分别记录“工具可打开”“条目语义一致”“提取负载一致”“归档字节一致”。任何前三项通过都不能自动推出第四项；实际工具输入/输出哈希必须与项目内部 staged-validator 证据分开绑定。

### 下次建议
为每个外部 GUI 工具建立自主合成输入、固定工具哈希、操作步骤、输出哈希和恢复外部状态的记录；自动包装器只声明它能实际证明的字节验证范围。
