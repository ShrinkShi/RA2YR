# Palette and LAT binding

## 1. Palette boundary

TMP color and extra-color bytes are palette indices. The TMP file does not contain a palette and does not select one by itself.

The theater profile supplies logical palette bindings, typically separating:

- ISO/terrain palette for TMP terrain graphics;
- unit palette for units, buildings, and some theater-aware objects;
- resource/tiberium/ore palette roles where applicable;
- UI/radar metadata, which is not simply another TMP indexed plane.

`unit*.pal` must not be used as the default TMP palette merely because it is available in the same theater.

## 2. Palette binding result

Recommended structure:

```text
TheaterPaletteBinding
- TheaterKind
- IsoPaletteCandidateChain
- UnitPaletteCandidateChain
- ResourcePaletteCandidateChains
- SelectedLogicalCandidates
- SuppressedCandidates
- ResolutionDiagnostics
- EvidenceLevel
```

The TMP reader returns indices; a later adapter receives a successful palette binding and resolves colors.

## 3. Theater-specific palettes

Common community names include:

- `isotem.pal`
- `isosno.pal`
- `isourb.pal`
- NewUrban ISO-palette candidate
- `isodes.pal`
- `isolun.pal`

Exact logical names and fallback behavior belong to `TheaterProfileDescriptor`. They are not generated by replacing the TMP extension in a filename.

Palette candidates participate in the same deterministic content provenance system as other resources.

## 4. Radar metadata

The two three-byte radar color fields in each TMP cell header are stored as raw components. They should not be recomputed from the ISO palette during read.

Possible later uses include minimap left/right triangle coloring, but exact runtime interpretation is underconfirmed.

The binding layer must preserve the distinction between:

- indexed terrain color planes;
- raw radar metadata bytes;
- generated map preview colors;
- overlay radar colors.

## 5. LAT is not a palette operation

LAT connects terrain TileSets and transition TileSets. It does not convert palette indices.

A LAT binding candidate contains:

```text
TheaterLatBinding
- GroundTileSet
- TransitionTileSet
- BaseTileSet
- ConnectToTileSetIndices
- SourceKeyProvenance
- ValidationStatus
```

Traditional pairs include:

- rough ground and clear-to-rough LAT;
- sand and clear-to-sand;
- pavement and clear-to-pavement;
- green and clear-to-green.

Extension profiles can add additional `GroundN*` relationships. They must be labelled separately.

## 6. Morphable and Marble Madness

`Morphable`, `MarbleMadness`, and `NonMarbleMadness` are TileSet registry relationships. They are not TMP flag bits.

The project should model these as explicit edges with:

- valid/missing target;
- possible self-reference;
- cycle detection;
- source provenance;
- profile origin.

An editor may use these links to replace tiles for visualization or randomization. The Core binder must not mutate the source tile registry automatically.

## 7. Palette mismatch diagnostics

Suggested diagnostics:

- missing ISO palette;
- palette length invalid;
- multiple case-colliding palette candidates;
- fallback palette used;
- theater profile has no palette binding;
- TMP bound to a palette from another theater;
- unit palette supplied where ISO palette is required;
- palette candidate provenance incomplete.

No palette bytes or per-index color list should enter public audit output.

## 8. LAT validation

Validation includes:

- source and target TileSet indices exist;
- ground and transition ranges are non-empty;
- base TileSet exists or explicit default policy applies;
- connected indices are unique and in range;
- missing keys are distinguished from explicit negative/disabled values;
- extension keys do not silently alter vanilla profiles.

## 9. Modern rendering boundary

A later rendering adapter may build:

- textures;
- palette lookup textures;
- material variants;
- high-resolution replacements;
- PBR terrain assets.

These modern assets can be supplied by a higher provider, but their logical binding must preserve the underlying theater/TileSet/global-tile identity and cannot change legacy ID allocation.

## 10. Evidence status

| Claim | Grade | Notes |
|---|---|---|
| TMP has no internal palette | `ConfirmedByMultipleIndependentImplementations` | Independent TMP readers expose indexed bytes without embedded palette data. |
| ISO palette colors TMP | `ConfirmedCommunityConvention` | Long-standing tool and modding behavior agrees; this is not original-runtime source proof. |
| unit palette is separate | `ConfirmedCommunityConvention` | Widely documented theater resource convention. |
| listed LAT pairs | `ConfirmedByOfficialToolSource` | Official editor evidence is primary; reimplementations corroborate the relationships. |
| radar fields are two RGB triples | `Underconfirmed` | Strong conventional naming exists, but component order and exact runtime use are not established. |
| NEWURBAN palette/fallback rules | `ImplementationSpecificBehavior` | Profile/editor-specific behavior requiring separate audit. |
